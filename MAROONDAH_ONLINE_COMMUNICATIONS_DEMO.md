# Maroondah Online Communications Demo Script

Target role: Online Communications / CMS / Website Content / Digital Channels

Project: Greenline Studio WordPress Delivery Project

Purpose of this document: Reframe the WordPress project for a communications-focused role. Keep the story focused on CMS publishing, content structure, website quality assurance, forms, analytics, and contributor training. Avoid going too deep into Docker, custom API, or plugin code unless asked.

## Positioning

### Main Message

This project demonstrates how I approach website content and online service delivery in a structured way: organising pages, checking forms, testing email pathways, reviewing website quality, documenting handover, and using analytics to evaluate user interactions.

### What To Avoid Over-Explaining

- Do not lead with Docker.
- Do not spend too long on custom plugin code.
- Do not describe the REST API unless asked.
- Do not frame the project as mainly a developer coding project.

### What To Emphasise

- CMS content structure
- Website publishing workflow
- Content governance and QA
- Online forms and service pathway testing
- GA4 / GTM analytics awareness
- Client / contributor training documentation
- Accessibility and best-practice mindset

## 2-Minute Video Script

Use this if you need a concise recorded walkthrough.

```text
Hi, I would like to briefly show my Greenline Studio WordPress project from an online communications and CMS perspective.

The purpose of this project was to practise the full workflow around a small business website, including content structure, forms, QA, analytics, and handover documentation.

First, the site itself shows how I organised pages, navigation, contact information, and service-style content in WordPress. My focus here was not just building pages, but making the website easy to understand, maintain, and update.

Second, I created a case study page with website audit and handover sections. These show how I think about content quality, publishing checks, maintenance responsibilities, and supporting non-technical contributors.

Third, I tested the contact form and email pathway using a local test inbox. For online services, I think it is important to verify that forms work properly and that the right notifications are received before publishing changes.

Fourth, I created GA4 and Google Tag Manager tracking notes and a small tracking demo. This shows how website interactions such as form submissions, CTA clicks, phone clicks, and email clicks can be measured and used for reporting.

Finally, I prepared a client training guide. It explains what content can be safely updated, what should be escalated, and what checks should be done regularly. This is the part that connects website delivery with content governance and contributor support.

Overall, this project shows that I can work with CMS content, test online service pathways, support website quality, understand analytics, and document processes clearly for other users.
```
